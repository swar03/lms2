✅ 1. Use Phase-Based Prompts
Break your build into these 6 logical phases:

Planning & Schema Design

Backend Development

Approval Workflow & Notifications

Frontend Dashboards

Testing & Certificate Logic

Deployment & Monitoring

Each prompt should focus on just one phase, with clear boundaries.

🧠 2. Start with Intent + Context
Begin every prompt with:

What you want to build

Why it matters

What tech stack you're using

Example:

“I’m building an LMS admin panel using Express + Prisma + PostgreSQL. I want to generate the Prisma schema for users, courses, modules, lectures, assignments, quizzes, submissions, and certificates. Each course has modules, each module has lectures, and students earn certificates after completing modules.”

🧩 3. Be Specific About Relationships & Logic
Don’t just say “build a user model”—explain how it connects.

Example:

“Each user can be a student, manager, or admin. Students submit assignments and quizzes. Admins create courses and modules. Managers can approve students. I want the schema to reflect these relationships with foreign keys and composite indexes.”

🔐 4. Mention Role-Based Access & Middleware
If your system has roles, always define them and their permissions.

Example:

“Use JWT-based auth. Admins can create/edit/delete courses. Managers can approve students. Students can only view approved courses and submit assignments.”

📦 5. Define API Routes & Expected Responses
Tell Vibe what endpoints you want and how they should behave.

Example:

“Create REST APIs for /api/v1/courses, /modules, /lectures, etc. Use standardized response format:

json
{
  "success": true,
  "data": {...},
  "message": "Course created successfully"
}
🧪 6. Ask for Production-Ready Code
Use phrases like:

“Production-ready”

“Scalable”

“Modular”

“With error handling”

“With pagination and rate limiting”

Example:

“Generate production-ready Express routes for course CRUD with pagination, error handling, and role-based access control.”

🧰 7. Use Follow-Up Prompts to Refine
After Vibe generates code, you can say:

“Add soft delete logic”

“Include audit logs”

“Make it compatible with AWS EC2 deployment”

“Add Socket.IO for real-time notifications”
